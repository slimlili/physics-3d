# 物理三维演示生成流程

工具目录：`~/tools/physics-3d`（模板、脚本、物理函数；你不直接改）
输出目录：`~/磁场三维演示/`
命名：`<YYYYMMDD>-<题号或主题>-<slug>.html`，例如 `20261111-15-回旋加速器.html`

## 六步，不可跳过

1. **复述**（必须先说，等用户确认或指出错误）：两句话讲清——什么场、什么粒子、几何关系、要求什么。例如「这是 T2：磁场在直线边界右侧，粒子从左方以 30° 射入，问在磁场中走多久」。
2. **判模型**：查下面的判定表。判不了就明说「现有模板做不了」，给出最接近的模板和需要的增量，不要硬套。
3. **定几何**：坐标、正方向、场景比例（画面归一化，读数用题目真值）、题目给定值与显示值的关系。
4. **生成**：复制 `templates/` 里最接近的模板到 `templates/_instance.html`（必须留在 templates/ 下，否则 `../lib` 解析失败），改三处——`P`（题目数值）、标题/题目原文、答案面板；物理量一律调用 `src/physics.js`，**不手写公式**。生成后删掉临时文件。
   - **模板现状**：T1 已有「题目数值层」（`P` + `PHYS.fmt`，读数显示真值与科学计数）；T2/T3/T4 仍只有场景单位，实例化前需照 T1 补 `P` 层，否则读数是归一化数字。
5. **自检**：`python3 tools/build.py <模板> <输出>` → `.venv/bin/python tools/check.py <输出>`（无 venv 时 check.py 会自动降级，但跳过画面检查）。检查不过必须修到通过；再截图人眼看一次（穿模、方向、标签）。
6. **交付**：路径 + 三句话操作说明 + 本题题眼（哪一步是解题关键）。

## 判定表

| 题目特征 | 模板 |
|---|---|
| 只有磁场、速度垂直射入、无边界，问 r / T / 转过的角度 | `templates/t1-circular.html` |
| 直线边界，「恰好射出」「求弦长 / 圆心角 / 在磁场中的时间」 | `templates/t2-boundary.html` |
| 速度与磁场斜交，出现「螺距」 | `templates/t3-helix.html` |
| 电场与磁场同时存在，要求「直线通过」「选择速度」 | `templates/t4-selector.html` |
| 加速电场 + 速度选择器 + 圆形边界磁场的组合（先电场后磁场，垂直打在平板上） | `templates/t5-combo.html` |
| 圆形边界、临界、多段轨迹、回旋加速器 | 现有模板做不了：明确说明，按最接近的模板做增量，并把增量补进模板库 |

## 硬性要求

- 产物是**单文件 HTML**，不得引用任何网络地址（three.js 已本地化，build 会内联）
- 控件统一：四档播放速度、暂停、重播、空格暂停、R 重播、答案面板默认收起
- 读数用题目真实数值；题目只给符号时显示公式（在答案面板写解析式），**不得编造数字**
- 答案锁定题目条件；拖动滑块后用 `markDrift(true)` 提示「已偏离题目条件，读数仅供参考」
- 退化情况必须有兜底：B→0、v→0、θ→0 不能出现 NaN，读数显示「—」或 0

## 质量基线

- 生成后跑 `tools/check.py`：它会看标题是否 `*_OK`、读数与 `<script id="expect">` 是否一致、画面是否黑屏、有无未捕获错误
- 物理量改动时先改 `src/physics.js` 并跑 `jsc tests/physics.test.js`
- 模板改动后跑对应的 `tests/tN.render.test.py`
